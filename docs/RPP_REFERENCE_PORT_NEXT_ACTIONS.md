1. 在所属 `RPP_REFERENCE_PORT_AUDIT_XXX-YYY.md` 的原编号行补充**新证据、日期、结论**；若确认 CHS 没有相同 Bug，标记“无需修复”，不要删掉历史。
2. 同步更新总台账、优先级总览及根目录 `TODO.md` 的**未完成事项**。已完成的实测和开发记录进入 `docs/CHS_ACCEPTANCE_HISTORY.md`。
3. 以当时**最新已提交 HEAD** 为补丁起点；按项目规则交增量/累计全量和中文 Commit（互斥补丁）。游戏功能改动须用新测试候选进行最小红蓝构建、必要场景运行验证，不能把静态 PASS 当作游戏 PASS。
