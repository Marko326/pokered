## 暂缓或不直接适用的参考系统

- **Crystal Audio**：例如 #004、#051～056、#060～063、#142、#244、#270、#272～276、#407～408、#435 等，要确认本地有无相同音频实现；CHS 当前没有参考引擎，不能把它的内部 Bug 当作 CHS Bug。
- **地区形态 + 独立图鉴**：#230～235、#329～330、#393～405 等，涉及物种 ID、图鉴、SRAM、图像、掉落/遭遇与兼容，需产品级设计。
- **扩招身份/MoveDex/回忆系统**：#418～438 等，牵涉原版 Move ID、四槽、盒子、交换、回忆、战斗 AI 及旧存档；不是单个可移植修复。
- **大型动画、分类背包、地图数据压缩**：#078～082、#134～168、#255～262、#301～327 等，投入高，收益和兼容成本需分别论证。
- **改变原版战斗规则**：例如 #011、#018、#290～291、#310～311、#439 等，未经明确要求不实施；部分 CHS 已另有相同规则或不同设计，要以当前源码为准。

## 下一步工作方式

1. 先让维护者按编号挑选。Bug 候选先设计独立复现、确认版本和影响，再做小型修复；新功能先决定玩法。
2. 每一项实施使用当前最新**已提交源码**为基线，代码补丁的增量/全量和中文提交日志按项目规范；文档评估不擅自增加游戏版本号。
3. 修复后的测试记录必须区分“源码静态检查”“红蓝构建”“DMG/CGB 实测”和“用户验收”；避免把待核验改写成已确认。
4. 15 份分批文档为审计来源，后续如核验否定某一候选，应明确更新该笔状态及原因，不静默删除。
