## 一、状态含义与工作规则

- **已实现**：当前 CHS 源码或验收历史证明已有**相同目标/结果**；不一定是相同实现。
- **部分实现**：CHS 已覆盖参考目标的一部分，但不能推断所有边界同样生效。
- **待核验**：参考分支修过 Bug，但 **CHS 未证实同一个 Bug 存在**。先复现，再决定是否需要修。
- **需评估**：新增功能、体验设定或玩法平衡；并不是“漏移植的 Bug”，由项目维护者选需求。
- **当前不适用**：参考依赖的音频/野外交互等系统在 CHS 不具备同等前提；并非 CHS 缺失功能的故障。
- **依赖暂缓**：必须和相关前置提交作为一组考虑，当前不应独立应用。

**按批推进**：建议每批 30 笔；每批写入单独 Markdown，确认后再将已审核状态追加到总台账索引。禁止把未审的剩余 412 笔自动标成未实现。除非另有明确开发要求，本批仅更新项目 `docs/`，不修改 `src/`、版本号、MAP、补丁或 Git 提交。
