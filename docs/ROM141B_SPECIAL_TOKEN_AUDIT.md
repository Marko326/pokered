## 1. 用户录像复现的问题

用户上传的 `66426.mp4` 显示，LANGUAGE=English 时，Viridian City 样本仍出现中文“宝可梦”，例如英文句子中出现“宝可梦 BALLs”及“宝可梦 MON”。这证明 ROM-1.41A 的英文样本没有实现真正的英文显示，不能验收通过。

## 2. 根因（源码核对）

这不是普通的字面字符串替换问题：

1. `src/home/text.asm` 的文字字典中有 `dict CHARVAL("#"), PlacePOKe`。
2. 因此源文本里的 `#` 不是普通井号，而是调用 `PlacePOKe` 的特殊文字指令。
3. `PlacePOKe` 通过 `PlacePOKeText` 输出统一的“POKé”文字。
4. CHS 翻译导入逻辑 `src/tools/_importText.py` 明确包含 `textReplacement = {'#MON':'#','#':'宝可梦','&':'训练家'}` 和反向替换表；中文版共享扩展结果因此是中文。
5. ROM-1.41A 的英文副本仍然写成 `#MON` / `# BALLs`，所以它们虽然从英文 far-text 地址读取，运行时却继续调用 CHS 的共享特殊文字扩展。

此前只核对英文 ASM 字面内容与原版一致，没有追踪 `#` 的运行时字典分派，也没有在 ROM 中验证展开结果。这是 ROM-1.41A 静态验证范围不足，不能把它记作通过。

## 3. ROM-1.41B 修正

仅在英文静态样本中，将特殊命令改为普通英文字符：

- `# BALLs` → `POKé BALLs`
- `#MON` → `POKéMON`

这样英文副本不再触发 CHS 的 `PlacePOKe` 扩展。`é` 在 `src/charmap.asm` 中有正常字符映射。两条英文样本的最长文本行是 17 个字符；仍需维护者构建并检查实际排版、分页和字体显示。

中文原文、中文 far-text 指针、`PlacePOKe` 的现有行为及其他游戏文本均未修改。当前修正只处理本次英文样本，不代表已解决全游戏所有特殊文字指令。

## 4. 后续必须建立的特殊文字指令审计

`src/home/text.asm` 还定义了多个运行时文字字典入口，例如：

- 需要检查语言输出的共享扩展：`#` / `PlacePOKe`、`<PC>` / `PCChar`、`<ROCKET>` / `RocketChar`、`<TM>` / `TMChar`、`<TRAINER>` / `TrainerChar`、`<PKMN>` / `PlacePKMN`。
- 必须保留动态语义、不能简单替换成固定字符串：`<PLAYER>`、`<RIVAL>`、`<USER>`、`<TARGET>`。
- 必须保留控制流程语义：`<CONT>`、`<PAGE>`、`<DONE>`、`<PROMPT>` 等。

以上是代码中已见到的字典入口分类，不表示每一项都已确认存在中文错误。后续必须逐项确认其实际输出字符串、翻译导入来源、英文模式行为及动态参数，再决定采用语言感知扩展、英文专用扩展还是普通英文文本。
